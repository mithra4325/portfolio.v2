Task 02: Adafruit IO MQTT Control

Overview

This task controls hardware through the MQTT protocol using the Adafruit IO cloud broker. A toggle switch on an Adafruit IO dashboard publishes ON or OFF to a feed. The ESP32 is subscribed to the same feed and switches a circuit soldered on a perfboard. A push button on the circuit works as a manual override and sends its state back to the dashboard.

Objective

  • Understand how MQTT works with a broker, topics, publishers and subscribers.
  • Create an Adafruit IO feed and dashboard with a toggle switch.
  • Connect the ESP32 to Adafruit IO and subscribe to the feed.
  • Build and solder a transistor driver circuit on a perfboard.
  • Control the circuit from the dashboard and from the push button.

Components

  • ESP32 development board
  • NPN transistor [[FILL: part number, e.g. BC547]]
  • Resistor for the transistor base [[FILL: value]]
  • LED or bulb as the load [[FILL: what you used]]
  • Push button
  • Perfboard, solder and wires
  • Digital multimeter for continuity checks
  • Adafruit IO account

Work

  1. Created an Adafruit IO account and a feed named "bulb". Adafruit IO feeds are MQTT topics in the format username/feeds/feedname.
  2. Created a dashboard [[FILL: dashboard name]] and added a Toggle block connected to the bulb feed. The toggle sends ON and OFF.
  3. Noted the Adafruit IO username and the Active Key. The key acts as the password for the MQTT connection and is not shared.
  4. Soldered the circuit on the perfboard. An ESP32 output pin goes through a resistor to the base of the NPN transistor. The emitter goes to ground. The load sits between the supply and the collector, so the transistor works as a switch. The push button connects an ESP32 input pin to ground and uses the internal pull-up resistor. Checked every joint for continuity with a multimeter before powering the board.
  5. Installed the Adafruit MQTT library in Arduino IDE and wrote the sketch. It connects to Wi-Fi, connects to io.adafruit.com on port 1883 and subscribes to the bulb feed.
  6. When the dashboard toggle is switched, the broker forwards ON or OFF to the ESP32. The ESP32 sets the output pin HIGH or LOW and the transistor switches the load.
  7. When the push button is pressed, the ESP32 flips the output and publishes the new state to the same feed. The dashboard toggle then updates to match.
  8. Tested from both sides. The dashboard switched the load, the push button switched the load, and the dashboard always showed the current state.

Code

File: ESP32_AdafruitIO_MQTT.ino
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

#define WLAN_SSID      "YOUR_WIFI_NAME"
#define WLAN_PASS      "YOUR_WIFI_PASSWORD"
#define AIO_SERVER     "io.adafruit.com"
#define AIO_SERVERPORT 1883
#define AIO_USERNAME   "YOUR_AIO_USERNAME"
#define AIO_KEY        "YOUR_AIO_KEY"

const int OUTPUT_PIN = 5;   // to transistor base through a resistor
const int BUTTON_PIN = 4;   // push button to GND

WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

Adafruit_MQTT_Subscribe bulbFeed = Adafruit_MQTT_Subscribe(&mqtt, AIO_USERNAME "/feeds/bulb");
Adafruit_MQTT_Publish   bulbPub  = Adafruit_MQTT_Publish(&mqtt, AIO_USERNAME "/feeds/bulb");

bool outputState = false;
int lastButton = HIGH;
unsigned long lastPress = 0;
unsigned long lastPing = 0;

void setOutput(bool on) {
  outputState = on;
  digitalWrite(OUTPUT_PIN, on ? HIGH : LOW);
}

void MQTT_connect() {
  if (mqtt.connected()) return;
  Serial.print("Connecting to MQTT... ");
  int8_t ret;
  uint8_t retries = 3;
  while ((ret = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(ret));
    mqtt.disconnect();
    delay(5000);
    if (--retries == 0) ESP.restart();
  }
  Serial.println("connected");
}

void setup() {
  Serial.begin(115200);
  pinMode(OUTPUT_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  setOutput(false);

  WiFi.begin(WLAN_SSID, WLAN_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWiFi connected");

  mqtt.subscribe(&bulbFeed);
}

void loop() {
  MQTT_connect();

  // Message from the dashboard
  Adafruit_MQTT_Subscribe *sub;
  while ((sub = mqtt.readSubscription(100))) {
    if (sub == &bulbFeed) {
      String msg = (char *)bulbFeed.lastread;
      Serial.print("Received: ");
      Serial.println(msg);
      setOutput(msg == "ON");
    }
  }

  // Manual push button
  int reading = digitalRead(BUTTON_PIN);
  if (reading == LOW && lastButton == HIGH && millis() - lastPress > 250) {
    lastPress = millis();
    setOutput(!outputState);
    bulbPub.publish(outputState ? "ON" : "OFF");
  }
  lastButton = reading;

  // Keep the connection alive
  if (millis() - lastPing > 30000) {
    lastPing = millis();
    if (!mqtt.ping()) mqtt.disconnect();
  }
}

Result

The Adafruit IO dashboard switched the soldered circuit from anywhere with internet access. The push button switched the same circuit locally and the dashboard toggle followed it. Both controls stayed in sync through the single bulb feed.

Learnings

  • MQTT uses a broker between devices. The dashboard and the ESP32 never talk to each other directly. They only publish to and subscribe from a topic.
  • MQTT messages are small, which makes it a better fit than HTTP for constant device updates.
  • An ESP32 pin can only supply a small current, so a transistor is used to switch the load.
  • Publishing the button state back to the feed keeps the cloud dashboard accurate.
  • Continuity checks with a multimeter before powering a soldered circuit find bad joints early.
  • The Adafruit IO key works like a password and stays out of public code.
